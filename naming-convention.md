# Naming Convention – конвенция про конвенции

> AIN3 · AI-Native Sprint III. Это выжимка рабочей конвенции, которая два года живёт в реальной системе: личный волт (2 200+ транскриптов), командный волт (5 100+ файлов, 876 транскриптов встреч), десятки git-репозиториев и агентские сессии Claude Code / Codex. Всё ниже проверено эксплуатацией, а не придумано для слайда.

---

## 1. Зачем имени файла быть договорённостью

Имя файла – первый индекс системы. Человек, агент и git читают один и тот же адрес:

- человек сканирует папку глазами и понимает содержимое без открытия;
- агент делает `grep`/`ls` по шаблону и находит контекст без векторной базы;
- git показывает историю по осмысленному пути, ссылки не ломаются при шаринге.

Пока файлов десять – конвенция кажется лишней. На тысяче файлов она заменяет каталог, поиск и половину онбординга. Дешевле всего ввести её в первый день.

## 2. Грамматика

```
{project} {type} description – YYYY-MM-DD.ext
```

| Элемент | Роль | Пример |
|---|---|---|
| `{project}` | где это живёт – код проекта/контура | `{ain3}`, `{crm}`, `{self}` |
| `{type}` | что это по жизненному циклу | `{brief}`, `{transcript}`, `{decision}` |
| `description` | о чём – 2–6 слов | `weekly pipeline sync` |
| `– YYYY-MM-DD` | когда – дата В КОНЦЕ, через en-dash | `– 2026-07-14` |
| `.ext` | формат следует роли памяти | `.md`, `.jsonl`, `.parquet` |

Полный пример: `{crm} {meeting} weekly pipeline sync – 2026-07-14.md`

### Жёсткие правила (выстраданы)

1. **Дата всегда в конце.** Дата в начале ломает алфавитную группировку по проекту; дата в середине не парсится глазами.
2. **Только среднее тире (–, en-dash, U+2013)** перед датой. Дефис сливается с описанием, длинное тире (—) запрещено во всей системе. Mac: `Option + -`.
3. **Имя файла – латиницей.** Содержимое может быть на любом языке; имя – английское. Причина: стабильные URL, git без сюрпризов кодировки, шаринг наружу (Netlify, GitHub, партнёры) без `%D0%9F...`.
4. **Переименование задним числом запрещено массово.** Конвенция применяется forward-only: новые файлы – по правилу, старые живут как есть (массовый rename ломает внутренние ссылки). Точечный rename – только вместе со свипом всех ссылок на файл.

### Служебные исключения

| Имя | Почему вне схемы |
|---|---|
| `AGENTS.md` / `CLAUDE.md` | router-файлы, агент ищет их по точному имени до первой задачи |
| `README.md` | контракт GitHub |
| `SKILL.md` | контракт скилл-движка: папка = имя скилла, файл всегда SKILL.md |
| скрипты и конфиги | английский kebab-case: `deck-save-server.py` |

## 3. Три контура – одна грамматика

Конвенция масштабируется без изменения формы: меняется только словарь `{project}` и `{type}`.

### personal
```
{self} {rule} morning routine – 2026-07-01.md
{self} {transcript} therapy session notes – 2026-07-08.md
{channel} {article} ain3 personal invite – 2026-07-11.md
```

### team
```
{AIM} {program} AI-Native Sprint III Weekly Plan v1 – 2026-06-18.md
{AIM} {analysis} AIN03 Lab Data Snapshot – 2026-07-10.md
{AIM} {decision} 2026-07-10 on-demand-participants-snapshot.md
```

### model-data
```
rollout-2026-07-14T02-15-32-<uuid>.jsonl      # события сессии агента
{ain3} {labs dataflow} roster – 2026-07-10.md # автогенерируемый срез
evidence-log.md                                # журнал прогонов, append-only
manifest.json / edits.json                     # состояние артефакта
```

Формат следует роли памяти: `.md` – договорённости, правила, контекст (читают люди и агенты); `.jsonl` – события, диалоги, eval-кейсы (пишут машины, читают выборочно); `.parquet` – массивы для аналитики; `.sqlite` – индексированное runtime-состояние.

## 4. Минимальный словарь типов для старта

Не копируйте весь словарь зрелой системы – возьмите 6–8 типов и растите по мере надобности.

| Тип | Что это | Ключевое свойство |
|---|---|---|
| `{brief}` | operating brief процесса | trigger · inputs · output · owner · DoD |
| `{transcript}` | сырой источник (встреча, голос) | append-only, не редактируется |
| `{analysis}` | разбор, выводы | ссылается на источники |
| `{rule}` | правило системы | живёт долго, обновляется |
| `{handoff}` | передача между сессиями/людьми | 5–7 строк: состояние + следующий шаг |
| `{process}` | living how-to | редактируется при изменении процесса, поле `updated:` |
| `{decision}` | снапшот решения (ADR-паттерн) | одно решение = один файл, после принятия не редактируется – пишется новый со ссылкой на старый |
| `{research}` | исследование с источниками | source ledger внутри |

Пара `{process}` ↔ `{decision}` – главный приём зрелой системы: инструкция «как развернуть» живёт и правится, а каждое значимое изменение фиксируется отдельным неизменяемым снапшотом «почему».

## 5. Анти-паттерны (реальные, из аудитов)

| ❌ Было | ✅ Стало | Что чинит |
|---|---|---|
| `Untitled 14.md` | `{ain3} {notes} kickoff questions – 2026-07-13.md` | адрес вместо мусора |
| `отчет_финал_2 (1).md` | `{crm} {report} q2 pipeline – 2026-07-01.md` | версия через git, не через «финал_2» |
| `2026-07-14 встреча.md` | `{team} {meeting} sprint planning – 2026-07-14.md` | дата в конце, проект виден |
| `Обновление обвязки.md` | `{AIM} {research} harness refresh – 2026-05-30.md` | латиница – ссылка переживёт шаринг |
| папка `Новая папка/важное` | тип в имени + существующая папка | смысл в адресе, а не в иерархии |

## 6. Как завести СВОЮ конвенцию – мета-правило

Конвенция выше – образец, а не догма. Своя строится за 30 минут:

1. **Возьмите один процесс** (тот же, что в operating brief) и выпишите 10 последних файлов вокруг него.
2. **Выделите 3–5 кодов проекта** – по числу контуров, где реально живут файлы. Меньше лучше.
3. **Выделите 5–8 типов** – по жизненному циклу файла (что можно править, что append-only, что неизменяемо).
4. **Запишите грамматику в свой router** (`AGENTS.md` / `CLAUDE.md`) – правило работает, когда агент читает его до первой задачи.
5. **Новый код или тип добавляется в файл конвенции в момент появления** – конвенция сама живёт по правилу `{rule}`: living-документ с датой обновления.

Проверка качества: незнакомый человек (или свежая сессия агента) по одному только `ls` понимает, что в папке и с чего начать. Если нет – словарь недоопределён.
