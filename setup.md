# Setup – как собрать свой pack за вечер

> AIN3 · AI-Native Sprint III. Маршрут сборки личного harness вокруг одного процесса: слоёная модель, данные, которые меняют подход, пять стадий и протокол передачи. База – скилл `AIM-harness-setup` (v2.7), конденсат операционного опыта AI Mindset 2024–2026: 200+ production-скиллов, 13K+ заметок в Obsidian, лабораторные когорты, кросс-инструментный синк Claude Code ↔ Codex.

---

## 0. Слоёная модель 4+1

```
OPERATOR    – человек, проектирующий условия: вопросы, границы, owners, eval, lifecycle
   ↓ проектирует контур
HARNESS     – обвязка вокруг модели: router-файлы, context, permissions, evidence, naming
   ↓ принимает в себя
TOOLS + SKILLS – вызываемые способности (MCP, скрипты, git) + отчуждённые процедуры (SKILL.md)
   ↓ работают над
ENVIRONMENT – состояние мира: файлы, процессы, сеть, сервисы
   ↓ обращается к
AI MODEL    – способность (меняется у провайдера, вам не принадлежит)
```

Уравнение: **agent = model + harness**. Модель вы «заводите», harness – то, что вы носите между запусками. Таксономия слоёв – официальная Anthropic (апрель 2026); этот пак целиком живёт на слое harness.

## 1. Пять фактов, которые меняют сетап

1. **Tool output – 67.6% контекста агента, system prompt – 3.4%.** Большинство полирует 3.4% поверхности. Реальный рычаг – управление выходами инструментов: обрезка, подзагрузка по требованию, суммаризация.
2. **Scaffolding premium: одна и та же модель даёт 80.9% или 45.9%** на SWE-bench в зависимости от обвязки. Выбор harness теперь дороже выбора модели.
3. **Самосгенерированные скиллы дают ≈ 0 эффекта** (Tessl, 1 200 скиллов); написанные человеком из своей практики – **+16.2 п.п.** Скилл рождается из третьего повторения.
4. **Потолок 32 скиллов:** дальше хвост перестаёт находиться. Лекарство – hub-and-spoke router.
5. **Thin-harness:** Vercel сократил 15 инструментов до 2 – точность 100%, минус 37% токенов, ×3.5 скорость. Меньше сущностей, больше глубины.

## 2. Сетап за вечер – пять стадий

### Stage 1 · Context Discovery (15 мин)
Письменно: основная функция на 6 месяцев · 5–7 регулярных AI-задач (точные действия) · какие чаще раза в неделю (кандидаты в скиллы) · где сейчас живут промпты · что делегировали бы, но «долго объяснять» · чего боитесь, если выпадете на неделю · сколько runtime'ов у вас реально стоит.
**Выход:** портрет роли + список задач. Это ваш [operating brief](starter-pack/operating-brief-template.md).

### Stage 2 · Inventory (15 мин) – самая частая точка самообмана
Проверить, что УЖЕ есть: заметки/vault · конвенция имён · правила · конфиги runtime'ов · MCP-серверы · сниппеты промптов · синк между инструментами. Обычно 70% уже существует в рассыпанном виде.
**Выход:** gap-таблица «слой / есть / нет». Строите три недостающие ячейки, а не всё с нуля.

### Stage 3 · Первые три скилла (30 мин)
Три, не десять. Критерии: повторяемость (раз в неделю+) и отчуждаемость (описуемы процедура + контекст + критерии). Формат: папка + `SKILL.md`: trigger · steps 4–8 · output · evidence. В паке уже лежат два стартовых: [operating-brief](starter-pack/skills/operating-brief/SKILL.md) и [process-audit](starter-pack/skills/process-audit/SKILL.md).
**Выход:** скиллы, прогнанные на реальной задаче – не на выдуманной.

### Stage 4 · Каноничная структура (20 мин)
Router в корень ([`AGENTS.md`](starter-pack/AGENTS.md.template) / [`CLAUDE.md`](starter-pack/CLAUDE.md.template)) · [конвенция имён](naming-convention.md) · [source map](starter-pack/source-map-template.md) · папки `sources/ output/ skills/` (новые папки создаёт человек, не агент) · [agent passport](starter-pack/agent-passport-template.md) + [registry](starter-pack/agent-registry-template.md), если есть повторяющиеся агенты.
**Выход:** дерево, где каждый скилл занимает место. Правила слоя – [operating-rules.md](operating-rules.md).

### Stage 5 · Цикл оптимизации (постоянно)
Первый прогон – диагностика: output → gap → одна правка системы → [evidence log](starter-pack/evidence-log-template.md). Раз в 1–2 недели – [refresh ritual](starter-pack/refresh-ritual.md): выкинуть мёртвые правила, свежий взгляд на source map, один эталонный прогон. Скилл извлекается после 3+ ручных повторов; удаляется после 60 дней неиспользования.

## 3. Передача контура – handoff protocol

Когда контур работает, его можно передать (коллеге, команде, преемнику). Три позы одновременно:

1. **Assessment-first** – сначала пройти и оценить чужой контур (0–100 по слоям: absent / partial / mature), только потом рекомендовать. Тест зрелости: «переживёт неделю без владельца?»
2. **Non-prescriptive** – «более зрелый контур мог бы выглядеть так», не «ты должен». Решает человек.
3. **Bidirectional** – активно искать, где человек уже сильнее референса, и называть это. Передача в одну сторону провалена по определению.

Анти-паттерн: **self-report trap** – рассказ агента о самом себе не является evidence. Evidence – конфиги, процессы, логи, git history.

Шаблон передачи: [harness-setup-handoff-template.md](starter-pack/harness-setup-handoff-template.md).

## 4. Частые ошибки (проверено на когортах)

1. Начинать с инструмента вместо инвентаризации (stage 2).
2. Извлекать 10 скиллов сразу – один работающий дороже пяти «на всякий случай».
3. Хранить промпты в истории чата – чат не source of truth.
4. Полировать «идеальный промпт» вместо tool outputs (3.4% против 67.6%).
5. Ставить MCP-серверы без аудита прав.
6. Пропускать eval-петлю – без бинарной оценки не видно, где провисает.
